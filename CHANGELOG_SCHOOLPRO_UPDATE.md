# SchoolPro completion update

## Changes in this source package
- Admin approval screen requires manually entered Student ID and separate Admission Number for students, and manually entered Teacher ID for teachers. IDs are validated and never generated by the app.
- An admin-only `idRegistry` collection is used transactionally to prevent duplicate IDs among new approvals; existing user profiles are checked before approval as well.
- Student approval creates/updates `students/{uid}` with the same UID used by the account, so attendance can resolve the student record. Teacher approval creates/updates `teachers/{uid}`.
- Rejection supports a reason/correction note. Parent approvals do not receive student/teacher identifiers.
- Profile card displays separate Student ID, Admission Number, or Teacher ID fields.
- Registration supports up to eight optional supporting document images in addition to the mandatory profile photo.
- Placeholder SchoolPro logo/icon assets were added because the supplied ZIP referenced assets that were not included in the archive. Replace them with approved final artwork if needed.
- Firestore rules were updated locally to allow approval fields and the admin-only ID registry.

## Important limits / required verification
- Local source/rules changes only. No Firebase rules were deployed, no live data was changed, and no GitHub push was performed.
- Numeric email OTP / SMS OTP is not implemented; the app uses Firebase email verification links and password reset email.
- Rules must be tested against a staging Firebase project and reconciled with the existing Admin Web before any deployment. Audit existing records for duplicate IDs before rollout.
- The uploaded archive did not include iOS project files or Firebase iOS configuration, so iOS build is not verified.
- Compilation and runtime behavior still need verification in the user's Flutter/Termux environment; this workspace does not have Flutter installed.
